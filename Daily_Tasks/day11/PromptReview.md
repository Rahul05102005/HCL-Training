# Prompt Review

The two examples below are demonstrations of how prompt detail changes the result. The short example was written to show a plausible response to a vague request; it was not generated by an external AI tool.

## Vague prompt

> Create a Student class in Java.

The simple version is in `src/main/java/day11/examples/vague/Student.java`:

```java
public class Student {
    public String studentId;
    public String name;
}
```

## Specific prompt

> Create a Student POJO in Java with studentId, name, email, and department fields. Apply encapsulation using private fields and public getters and setters. Validate required fields and reject null or blank values where appropriate. Implement equals() and hashCode() consistently using studentId. Include a useful toString() method without exposing sensitive information. Follow Java naming conventions and keep the class simple.

The improved example is `src/main/java/day11/model/Student.java`. It keeps the identifier stable, validates text fields, and bases equality and hashing on that identifier.

| Area | Vague version | Specific version |
| --- | --- | --- |
| Fields | Only ID and name | ID, name, email, department |
| Encapsulation | Public fields | Private fields with accessors |
| Validation | None | Rejects null and blank values |
| Equality | Not defined | Consistent ID-based `equals` and `hashCode` |
| String output | Not defined | Shows useful details without email |

## What I learned

A specific prompt gives clear requirements to check during review. That makes missing behavior easier to spot and keeps the resulting class focused. The generated or drafted code still needs to be compiled and checked against those requirements.
