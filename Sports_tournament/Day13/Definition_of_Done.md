# Definition of Done

**Project:** Sports Tournament Management System (SportX)  
**Applies to:** US-01 through US-08 in this Day 13 backlog

A story is Done only when its agreed scope and acceptance criteria have been met and the checks below are complete. If a condition does not apply, the reviewer records why rather than silently skipping it.

## Completion checklist

### Scope and acceptance
- [ ] The story has a clear ID, description, and acceptance criteria linked to the intended requirement.
- [ ] Every acceptance criterion has been checked against the delivered behavior.
- [ ] Any scope change or known limitation is documented and agreed with the product owner or instructor.

### Implementation and code quality
- [ ] The implementation is complete and follows the project's conventions.
- [ ] Input and domain validation cover the relevant valid and invalid cases.
- [ ] Error handling gives a useful outcome and does not expose sensitive information.
- [ ] No known critical defect remains for the story.

### Testing and validation
- [ ] Relevant automated tests have been added or updated and pass.
- [ ] Relevant manual or integration checks have been completed where automated coverage is not suitable.
- [ ] Positive, invalid-input, and authorization/error cases have been checked where applicable.
- [ ] Existing related behavior has been checked for regressions.
- [ ] Results or blockers are recorded; a blocked or unrun check is not reported as passing.

### Review and documentation
- [ ] Changes have been reviewed by a peer or designated reviewer; requested changes are resolved.
- [ ] Relevant user, API, or project documentation is updated.
- [ ] The reviewer confirms the work matches the story and its acceptance criteria.

### Board and delivery
- [ ] The task has been updated on the GitHub Projects or Jira board with the final result and any relevant links.
- [ ] The status is moved to **Done** only after the preceding applicable checks are complete.
- [ ] Work that is still in progress, awaiting review, or blocked retains the appropriate status.

## Applying this checklist to this submission

This document defines a completion standard; it does not certify that the eight features have passed it. The Day 13 artifacts are prepared for board entry. The actual board and its statuses still need to be created or updated manually, and feature work should be marked Done only after its implementation and checks meet this definition.
